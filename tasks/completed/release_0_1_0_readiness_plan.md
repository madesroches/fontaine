# Release 0.1.0 Readiness Plan

**GitHub Issue**: https://github.com/madesroches/fontaine/issues/80

## Overview

Issue #80 tracks everything left before the first release. Most of its checklist needs live
provider keys, a live model, a Hugging Face token or a maintainer decision: the label sign-off, the
live scorecard, the `claude -p` baselines, the cassettes, the manual verification, the repository
setting and the tag itself. Those stay human steps, as do two of the PromptGuard 2 checks: the logit
spike against the model card and a live `scanner = "pg2"` session. The `FONTAINE_PG2_MODEL`
inference test was run against the real weights, which found item 7. This plan covers the
repo-side work that can land now, so that once the human items are done, cutting `v0.1.0` takes
only the tag:

1. Release archives ship the `LICENSE`, `README.md` and `CHANGELOG.md`. Today they hold only the
   binary, and Apache-2.0 §4(a) requires a copy of the license to go with redistributed binaries.
2. The GitHub Release body carries the version's changelog section. Today cargo-dist never sees
   the changelog.
3. A tag with no changelog section for its version fails the release before anything is built,
   instead of shipping without notes.
4. `CHANGELOG.md` holds a curated 0.1.0 entry in place of the per-phase development log.
5. `CONTRIBUTING.md` gets the maintainer's release procedure.
6. The master plan's `## Remaining work` is brought up to date: the merges and both bugs are done.
7. The PromptGuard 2 loader opens the real `meta-llama/Llama-Prompt-Guard-2-86M` files. It could
   not, and pg2 ships in the release binaries.

## Design

### Archive contents (`rust/fontaine/Cargo.toml`)

```toml
[package.metadata.dist]
dist = true
features = ["pg2"]
# The license, readme and changelog live at the repository root, outside the dist workspace
# (`rust/`), so auto-include cannot find them.
auto-includes = false
include = ["../../LICENSE", "../../README.md", "../../CHANGELOG.md"]
```

`include` paths are relative to the package's `Cargo.toml`. Each archive then holds `CHANGELOG.md`,
`LICENSE`, `README.md` and `fontaine`, as checked with a local `dist plan`. `auto-includes = false`
makes the asset list the same whether or not the release jobs have staged a `rust/CHANGELOG.md`
(next section). Without it, a staged copy would be auto-included as a second candidate in some jobs
but not in others.

### Release notes (`.github/workflows/release.yml`)

For a plain `vX.Y.Z` tag dist reads a changelog only from the workspace root (`rust/`). So the two
jobs whose announcement is used, `plan` and `host`, copy the root changelog into the workspace before any
`dist` command:

```yaml
      # dist reads release notes only from the workspace root (`rust/`); the changelog lives at
      # the repository root.
      - name: Stage the changelog for dist
        run: cp ../CHANGELOG.md CHANGELOG.md
```

The step goes right after checkout in both jobs. The build jobs also compute an announcement, but the
`host` job rebuilds the notes itself and ignores theirs; they take the changelog through `include`,
so they are not touched. The copy is never committed, because
it exists only in the runner's checkout. `rust/CHANGELOG.md` also goes into `.gitignore` for a
maintainer who reproduces the step locally.

### Missing-notes guard (`.github/workflows/release.yml`, `plan` job)

A new step runs right after the existing `id: plan` step, and only on a tag push
(`if: ${{ !github.event.pull_request }}`). That step's `dist host --steps=create` writes
`plan-dist-manifest.json`, which the guard reads:

```yaml
      - name: Require a changelog section for the tag
        if: ${{ !github.event.pull_request }}
        run: |
          if ! jq -e '.announcement_changelog != null' plan-dist-manifest.json > /dev/null; then
            echo "::error::CHANGELOG.md has no section for ${{ github.ref_name }}; add '## [X.Y.Z] - YYYY-MM-DD' before tagging"
            exit 1
          fi
```

`host --steps=create` writes nothing on GitHub; the release is created only by the `host` job, which
never runs when `plan` fails. On pull requests the guard is skipped, because the changelog
legitimately has only `## [Unreleased]` there.

### Changelog (`CHANGELOG.md`)

Replace the body of `## [Unreleased]` with a curated first-release entry under a single
`### Added`, written for a user and grouped by area. It is still headed `## [Unreleased]`, because
the release date is only known when the maintainer tags. The areas are:

- **Agent and models**: the agent loop over rig, `[accounts.<name>]` with `<account>/<model>`
  (Anthropic, OpenAI, Gemini, Ollama, OpenAI-compatible), `fontaine auth login`, sessions with
  `--continue` / `--resume` / `--fork-session`, and the system prompt with `FONTAINE.md`.
- **Configuration**: the settings scope stack (user, project, project-local, `--settings`) and its
  merge rules, project-local settings, project scope can only tighten, and an unknown key is a
  config error (exit code 2).
- **Tools**: the built-in tools, workspace roots and `--add-dir`, the risk class on every tool.
- **Permissions**: the modes (`manual`, `acceptEdits`, `plan`, `dontAsk`, `auto`), the
  deterministic floor, rules, the shell pre-classifier, the audit log, workspace trust.
- **Guardian**: auto mode, profiles, the ranked model list (empty until the scorecard), the
  denial UX and `/denied`, and the tool-result scanner (`off`/`pg2`/`llm`/`command`) with the
  Llama 4 license notice.
- **Terminal UI and headless**: the TUI, `fontaine -p` with the versioned headless contract and
  JSON Schema, and the exit codes.
- **Extensibility**: subagents and the agents panel, MCP, user hooks, skills, agent files and
  output styles.
- **Telemetry**: micromegas and OTLP, opt-in content, and which spans and events are exported (Fontaine's own target and the model
  layer's completion and agent targets).
- **Evals**: the golden dataset and `fontaine-evals` (fixture, `none` and `live:` modes, as
  `evals/README.md` documents them).
- **Distribution**: release binaries for Linux, macOS and Windows with `pg2`, and
  `cargo install --git`.

Rules for the rewrite:

- Every entry describes behavior that is in the build today, which is the bar `docs/` already
  meets. Each area's lines are written by reading the matching `docs/` page, not by paraphrasing
  the old log.
- Changes that only matter against earlier unreleased builds are dropped, such as the inline-TUI
  change, the removal of `echo`, error-text rewordings and the macOS CI fix.
- Issue references (#46, #73, #78, #85, #88) stay only where the entry still describes
  shipped behavior, such as queued messages, the `webfetch` User-Agent and `Accept` header and the Windows Git Bash
  command passing.
- No phase labels: the phase history lives in the plan and git.
- `### Changed`, `### Removed` and `### Fixed` are dropped. A first release has nothing to change
  from.

### Release procedure (`CONTRIBUTING.md`)

Add a `## Releasing` section for the maintainer:

1. Every release-readiness item in the release's tracking issue except cutting the tag itself is ticked. For 0.1.0 that is #80,
   mirrored in the master plan's `## Remaining work`.
2. Bump `[workspace.package] version` in `rust/Cargo.toml` if needed. For 0.1.0 it is already
   `0.1.0`.
3. In the release commit, rename `## [Unreleased]` to `## [X.Y.Z] - YYYY-MM-DD` and add a fresh,
   empty `## [Unreleased]` above it.
4. Install dist with the pinned installer the workflows use
   (`curl --proto '=https' --tlsv1.2 -LsSf https://github.com/axodotdev/cargo-dist/releases/download/v0.32.0/cargo-dist-installer.sh | sh`),
   the version matching `cargo-dist-version` in `rust/Cargo.toml`. From `rust/`, check the notes with
   `cp ../CHANGELOG.md CHANGELOG.md && dist plan --tag vX.Y.Z --output-format=json | jq .announcement_changelog`
   (non-null), then remove the copy.
5. Merge to `main`, then tag `vX.Y.Z` on the resulting merge commit on `main` and push the tag. The release workflow builds
   the archives and publishes the GitHub Release. Pushing the tag is always the maintainer's step.

The existing "add an entry under `## [Unreleased]`" bullet stays as it is.

### PromptGuard 2 loader (`rust/fontaine-guardian/src/scanner/pg2.rs`)

- When `config.json` has no `id2label`, default to `{0: LABEL_0, 1: LABEL_1}`, as transformers does.
  `malicious_class` already falls back to the highest class for unnamed labels. The
  `.ok_or("config.json has no id2label")` in `open` goes away, and `malicious_class`'s error text
  becomes "config.json has an empty id2label", since it can then only fire for a present-but-empty
  `id2label`.
- Load with `weights.pp("deberta")`. candle-transformers 0.11.0's
  `DebertaV2SeqClassificationModel::load` takes the backbone from the given builder and the
  pooler and classifier from `vb.root()`, which matches the standard
  `DebertaV2ForSequenceClassification` layout.

With both fixes, `FONTAINE_PG2_MODEL=<dir> cargo test --release -p fontaine-guardian --features pg2 --test pg2`
passes 2/2 against the real PromptGuard 2 weights, and against
`protectai/deberta-v3-base-prompt-injection-v2` (labels SAFE/INJECTION). A debug build exceeds the
test's 300 s load timeout, so that test needs `--release`.

## Trade-offs

- **Staging the changelog in the workflow vs. a `rust/CHANGELOG.md` symlink.** A symlink would make
  local `dist plan` show the notes with no extra step. But Windows checkouts without
  `core.symlinks` turn it into a text file holding `../CHANGELOG.md`, and the Windows build job
  runs on such a checkout. The copy is confined to the two Linux jobs that need it.
- **Staging vs. moving `CHANGELOG.md` into `rust/`.** The root layout rule in `AGENTS.md` fixes
  `CHANGELOG.md` at the root.
- **Curated 0.1.0 entry vs. keeping the per-phase log.** The section becomes the public release
  notes, and most of the log describes changes between unreleased builds. Git history keeps the
  detailed record.

## Testing Strategy

Apart from the pg2 loader, the changes are cargo-dist configuration, GitHub Actions steps and
prose, so there is nothing for a unit test to call.

- Offline regression test in `pg2.rs`, under the `pg2` feature: write a tiny safetensors file with
  the real naming layout (`deberta.`-prefixed backbone, root `pooler.dense` and `classifier`) and a
  `config.json` without `id2label` into a tempdir, and call `Loaded::open` (or `Pg2Scanner::load`)
  on it. `Loaded::open` also reads `tokenizer.json`, so the fixture writes one (save the WordLevel
  tokenizer that `model_tests::tiny` builds with `Tokenizer::save`), reuses `SMALL_CONFIG` without its
  `id2label` line, and produces the weights by building the model on a `candle_nn::VarMap` via
  `VarBuilder::from_varmap(..).pp("deberta")` and calling `varmap.save(...)`. It pins the bug that the shipped loader could not load the real PromptGuard 2.
- The real-weights test in `tests/pg2.rs` stays skipped without `FONTAINE_PG2_MODEL`; its doc comment
  says to run it with `--release`.

- `rust/fontaine-core/tests/docs.rs` already checks that `CHANGELOG.md` exists with content
  (`the_required_pages_exist_with_content`), and its link and placeholder checks (`checked_files`)
  cover `docs/*.md`, `README.md` and `evals/README.md`, so the README's relative links are covered.
  `CHANGELOG.md` and `CONTRIBUTING.md` are only checked to exist with content.
- `release.yml` runs on every pull request in `pr-run-mode = "plan"`. The PR for this branch runs
  the `plan` job with the staging step and with the guard skipped. A typo in an `include` path is not caught by
  `dist plan`; it fails only at `dist build` time (a tag push) or locally with `dist build`. Manual
  Verification step 1 confirms the asset names.
- The full offline gate set from `AGENTS.md` (`fmt`, `clippy`, `test`, `deny`, the fixture eval
  runs) stays green.

## Manual Verification

The tag-push path of `release.yml` runs only on a pushed tag, and pushing tags is the maintainer's
step. So the guard and the notes are checked locally with the pinned dist binary, which runs the
same `dist plan` the workflow runs:

1. From `rust/`: `dist plan --tag v0.1.0 --output-format=json | jq '.artifacts["fontaine-x86_64-unknown-linux-gnu.tar.xz"].assets | map(.name)'`.
   Expected: `["CHANGELOG.md", "LICENSE", "README.md", "fontaine"]`.
2. `cp ../CHANGELOG.md CHANGELOG.md && dist plan --tag v0.1.0 --output-format=json | jq -e '.announcement_changelog != null'; s=$?; rm CHANGELOG.md; echo "exit $s"`.
   Expected: `exit 1`. The changelog still says `## [Unreleased]`, so this is the guard's failing
   case.
3. Repeat step 2, in the same `s=$?; rm CHANGELOG.md; echo "exit $s"` form, with a scratch copy whose
   heading is renamed to `## [0.1.0] - 2026-10-23`. Expected: `exit 0`, and `.announcement_github_body` starts with `## Release Notes` followed by
   the curated entry.
