## Tests owned by this phase

- **config** (`tasks/design/testing.md` Testing Strategy): config errors assert the error variant that maps to `ExitCode` 2 (plus a bin-level exit-code assertion in `rust/fontaine/tests/exit_code.rs`); workspace = canonicalized launch cwd; project config
  discovered only at `<workspace>/.fontaine/settings{,.local}.toml` (a settings file in a parent directory is
  ignored); precedence (the managed slot is empty in v1), project-can-only-tighten enforcement —
  including that `[guardian] profile` is rejected from project scope (user trust scopes only, it is a
  loosening knob) and only `full`/`minimal` validate: no config value disables the guardian. Scope-rejection is table-driven over every "no"/limited cell of the `tasks/design/config.md` §Config scope
  table, for project, project-local and CLI `--settings` scopes (incl. user-file-only `[guardian] scanner*` keys rejected from CLI and project-local). Scope stack: CLI > project-local > project
  > user precedence for scalars and union for lists; a same-name `[accounts.<name>]` entry is replaced whole by the higher scope, not merged (same for `[mcp.servers.<name>]` and `[agents.types.<name>]`); `[[hooks.*]]` arrays union; `[telemetry] resource_attributes` set in two scopes merges per key, higher scope winning a shared key; project and project-local
  `default_mode` accept only `manual`/`dontAsk` (`"plan"`, `"acceptEdits"`, `"auto"` rejected from both); `[permissions] allow` / `additional_directories`
  rejected from project scope; unparseable rule strings and rules naming an unknown tool rejected; an unknown key or misspelled section (e.g. `[permisions]`) rejected in every scope (exit 2); `default_mode = "auto"` rejected (exit 2) from user and CLI scope until Phase 4; a missing `--settings` path and a project settings path that is a directory (non-NotFound I/O error; the test creates the directory, so it runs on all three OSes) are each a config error (exit 2) naming the path.
- **project-local trust classification** (`gix`, temp git repos): an untracked `settings.local.toml` and an ignored one in a trusted root load as user trust; an untracked one in an untrusted root loads as project scope (loosening key ⇒ exit 2, message names the untrusted root and the `trust.toml` hand-edit remedy); in a trusted root, a corrupt `.git/index` with an untracked `settings.local.toml` and a `.fontaine` symlink to a directory outside the work tree both load as project scope; a hand-made `.git` skeleton without trust ⇒ project scope; a repo with no index file (fresh `git init`) counts as an empty index; a tracked one loads as project scope, including a tracked file in a subdirectory path (e.g. `sub/dir/settings.local.toml` under a launch dir at that subdirectory) on every OS (Windows `\` separators must not make it look untracked); a tracked symlinked `.fontaine` dir (`.fontaine -> cfg/`, tracked `cfg/settings.local.toml`) and a case-variant tracked file load as project scope; a force-added `settings.local.toml` matched by `.gitignore` loads as project scope; a directory with no work tree loads as project scope; a launch from a subdirectory of the repo and a launch from a git worktree (`.git` file) classify an untracked `settings.local.toml` in a trusted root as user trust; a repo config with `core.fsmonitor` set to a canary command never executes it.
- **dirs** (unit tests in `dirs.rs`): `FONTAINE_CONFIG_DIR` / `FONTAINE_DATA_DIR` override the `dirs` defaults; an unresolvable dir with no override ⇒ config error (exit 2) naming the variable (tests pass `None` defaults and a constructed env-lookup closure; other tests pass dirs and a closure to the loader).
- **owner-only** (`owner_only.rs`; the `--debug-file` output in `rust/fontaine/tests/debug_file.rs`): owner-only files are 0600 on Unix and current-user-only on Windows, including a pre-existing 0644 file tightened before writing (`#[cfg(windows)]` ACL test, compile-checked locally with the windows-gnu target and executed in the windows CI job).
- **credentials lookup**: account entries and the telemetry entry round-trip from a temp `credentials.toml`; an account named `telemetry` does not shadow the telemetry key; a missing file or entry yields no credential; an unparseable file and a non-NotFound I/O error (the test creates a directory at the credentials path, so it runs on all three OSes) are each a config error (exit 2) naming the path.
- **trust store**: a trusted repo root trusts its subdirectories; a trusted subdirectory trusts neither its sibling nor its parent; a trusted entry above the work-tree root (a `$HOME`-like dir) trusts neither a repo inside it nor its untracked `settings.local.toml`; outside any repo, a trusted ancestor trusts a descendant directory; a discovery error other than not-found (e.g. a repo whose `.git/config` is unparseable) ⇒ not trusted even under a trusted `$HOME`-like entry; a non-canonical but equivalent recorded path (symlinked parent) still matches; the record is written under
  the data dir, never inside the workspace; `trust.toml` is 0600 on Unix (ACL under `#[cfg(windows)]`); an unparseable `trust.toml` trusts no root.
- **debug file** (`rust/fontaine/tests/debug_file.rs`): `--debug-file` writes debug-level events (the config-load event is present); `FONTAINE_LOG=warn` with `--debug-file` drops them (the config-load event absent); `FONTAINE_LOG` without `--debug-file` writes no file and nothing to stderr; an unparseable `FONTAINE_LOG` directive and an unopenable `--debug-file` path each exit 2 naming the flag/var.
- **telemetry config**: every `[telemetry]` key rejected from project and project-local scope except
  `enabled = false`; `enabled = true` without `endpoint`, or without a resolvable ingestion key (no
  `api_key_env` and no stored credential, or the named env var unset/empty), is a config error (exit
  2).
- Golden-dataset schema validation; the seed dataset meets the minimum counts in `tasks/design/testing.md` (per attack class, benign, ambiguous-intent); runner green against verdict fixtures; fixture mode exits 1 on a schema-invalid case or a `fixture_verdict` / `expected` mismatch, a `pipeline` case's `fixture_verdict.tier` / `expected_tier` mismatch, or an unparseable `permissions` rule string (`rust/fontaine-evals/tests/fixture.rs`); `--profile minimal` scores exactly the `profile = minimal` cases plus full-profile `guardian` cases (no full-profile `pipeline`/`scanner` cases); `--filter attack:*` and `--filter <kind>` restrict scoring while schema validation still covers the whole dataset; `--out` writes the per-case JSON and summary.
- **docs** (`rust/fontaine-core/tests/docs.rs`, run by `cargo test`; ```toml blocks fenced `toml trust.toml` / `toml credentials.toml` validate against that file's schema, plain ones as settings): the contract in `tasks/design/testing.md` Testing Strategy, docs bullet.
